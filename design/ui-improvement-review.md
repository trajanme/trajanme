# daywizz UI改善・検証記録

## 方針と範囲

StyleSeed 5.0.0のアーティファクト別バンドルと、提供されたブランドREADME・CSS・SVGを基準に改善しました。
共通シェル、ホーム、プロフィール、記事一覧・詳細、問い合わせ、アプリ紹介・サポートが対象です。
法務ページは共通書体・色・ナビゲーションを適用し、既存の文面を維持しています。

| 用途 | 有効な規則 |
| --- | --- |
| ホーム・プロフィール・アプリ紹介 | expressive-marketing × product-ui × expressive-brand |
| 記事・サポート・法務 | editorial-reading × product-ui × editorial-authority |
| 問い合わせ | consumer-service × product-ui × calm-consumer |

ホームはcontent / landing、PawStepsはhealth / landing、Picolle.はeducation / landing。
記事はcontent / list・detail、問い合わせはcontent / formです。
すべて共通のインポート済みトークンを使用し、追加の美的プロファイルは指定していません。
`quiet-mineral`は互換性のための設定名で、プリセット配色の生成・適用は行っていません。
補助色・余白・角丸はセットアップ時の初期案を使用し、元ロゴの実色と区別する出所記録を維持しています。

## デザイン上の契約

- 読者はアプリの利用を検討する人、地域・業務の相談先を探す人、記事やサポートを読む人。
- ホームの最初の画面で、地域に向けた目的と実際のプロダクト、次の行動が分かること。
- 森の共通ヘッダーと白い正規ロゴ、生成りの本文、墨の文字。橙は画面の主要行動に限定すること。
  アプリの元画像に含まれる色は、装飾的なUIアクセントとは区別します。
- 実際のアプリ素材を使い、架空の利用者数・成果・地図・写真を追加しないこと。
- 比較するアプリ紹介は同じ構造、記事は読みやすい行と余白で扱うこと。
- 動きを待たずに読めること。押下の短いフィードバックだけを使い、キーボード・低減モードでは移動を加えないこと。
- Astro、既存のルート、ストアURL、公開・準備中の区別、記事、FAQ、法務文面を保持すること。

anti-ui-slopのpolish / craftを適用し、既存画面と提供ブランドを根拠に確認しました。
有料UIZZEの参照取得は使用していません。Claude Artifactの見た目を確認したという主張もしていません。

## Emil Design Engineeringによる操作の見直し

| Before | After | Why |
| --- | --- | --- |
| マウスホバーだけで開くアプリ一覧 | ネイティブdetails、クリック・Space、Escape・外側クリック・フォーカス離脱で閉じる | タッチ・キーボードでも同じ導線を使える |
| 開閉状態やキーボード復帰が不足したモバイルメニュー | 名前のあるsummary、Escapeで閉じてトリガーへ復帰、幅変更時も閉じる | 状態と現在位置を見失わない |
| `transition-all`とカードの持ち上がり | 色・transformの対象指定、ボタンの140ms・scale(.98)の押下反応 | 不要な動きを減らし、押下にだけ応答する |
| FAQの手動JS開閉 | ネイティブdetails / summary、開閉に応じた＋／− | JavaScriptがなくても回答を読める |
| タグの色だけが変わる | aria-pressed、件数のライブ通知、該当なし・全件復帰 | 選択と結果が視覚以外でも分かる |
| メール送信と誤認しやすい問い合わせ | 「メールの下書きを作成」、送信先と起動しない場合の案内、入力内容を保持 | メールアプリでの送信完了が必要なことを正確に伝える |
| 押下・モーション低減の扱いが不統一 | 可変の短いCSS transition、focus-visible中は押下移動なし、低減モードでtransformを停止 | 頻繁な操作を遅らせず、動きの好みに応える |

## 必要な状態と確認範囲

| 状態 | 実装・確認 |
| --- | --- |
| 初期表示 | ホームを1440×900・390×844で表示。2倍解像度の全体PNGを保存し、画像を開いて確認 |
| ナビゲーション | PCメニューのクリック・Space・Escape、モバイルの開いた表示、タグへのTab順をChromeで確認 |
| FAQ | PawStepsサポートの回答表示とSpaceによる開閉をChromeで確認 |
| 選択状態 | モバイルの記事タグ「お知らせ」が選択され、表示が2件から1件に変わることをChromeで確認 |
| 空状態 | 記事0件とタグ該当なしの案内・復帰を実装。現データには記事があるため、ブラウザーで空状態を強制表示してはいない |
| エラー | 空の問い合わせフォームで、エラー案内・ネイティブの必須入力案内・名前欄へのフォーカス移動を確認 |
| メール下書き | 日本語・改行・特殊記号を保持するmailtoを、実際のページで使用する関数に対してテスト。OSのメールアプリへの引き渡しと実送信は未検証 |
| 読み込み | 静的生成ページなので、クライアントのデータ取得スピナーは対象外。画像に代替テキスト、長い画面では遅延読み込みを維持 |
| キーボード・フォーカス | スキップリンク、見えるフォーカス、メニュー・タグ・FAQ・必須フォームの操作を実装。主な操作を実画面で確認 |
| 低減モード | Chrome DevToolsでprefers-reduced-motion: reduceを有効にしてホームを確認。検証後にエミュレーションを解除 |
| アプリ紹介 | Picolle.のモバイル表示とストアへのリンク表示を確認。ギャラリーは名前のあるフォーカス可能な領域にし、スクロールバーを復帰 |
| 準備中 | omiyaの準備中表示を維持。プロフィールのリリース済みという矛盾をデータに合わせて修正 |

UI確認は、ブラウザー連携ホストが利用できなかったため、ネイティブChromeの画面操作とDevToolsのレスポンシブ表示で行いました。
全21アーティファクト・全状態の両サイズを網羅したという主張ではありません。
自動的な余白計測、全グリフのフォント監査、実機タッチ、全支援技術の検証は実施していません。
ホームの最終画像では、開発ツールバーがコンテンツに重ならないようAstroの開発ツールバーを無効にしています。

## 実行結果と再確認コマンド

- `npm run build`: 成功。16ページを生成。
- `npm run test:ui`: 5件成功。内部リンク・アセット・アンカー、ルート設定、タグ判定、mailtoの文字保持、法務文面の保持を確認。
- StyleSeedの全21アーティファクトのコンパイル整合性チェック: 成功。
- 全21アーティファクトの決定的チェック: ブロッキング0件。
- `git diff --check`: 成功。

決定的チェックは警告を残しています。元SVGの固定色、設定から生成した空間CSSの寸法、レスポンシブの境界、アプリ素材の表示寸法です。
ロゴの色を変えたり、スキャン対象を除外したりして警告を隠す処理は行っていません。
これはローカルのレビュー記録です。正式なevidence-gateの全ゲートへの添付や、人の受け入れ承認を完了したという主張ではありません。

```sh
node .agents/skills/styleseed/workflows/ss-resolve/scripts/resolve-context.mjs --project-root . --all --agent codex --check
npm run build
npm run test:ui
node .agents/skills/styleseed/workflows/ss-score/scripts/styleseed-check.mjs scan --project-root . --all --format json --gate
```

空間設定を変更したときは、先にバンドルを再コンパイルし、`node scripts/sync-styleseed-spacing.mjs`で実装CSSを同期します。

## 文言の追補

ユーザーの追加要望により、ナビゲーション・ホーム・記事一覧・プロフィールの呼称を「活動の足跡」に統一しました。
記事一覧の紹介文は、アプリ開発だけでなく地域での取り組み・今後の事業・出会いを含む内容に変更しました。
ホームに「まずは拠点のある関西から、小さく始めて、続く形を育てていきます。」を加え、プロフィールにも兵庫を拠点とした関西への思いを添えました。
この方針はStyleSeedのD-014に記録しています。

追補後もビルド・5件の既存テスト・設定整合性・差分チェックは成功しました。
追補後の画面再確認はネイティブ接続の起動失敗により実施できていません。
上記のスクリーンショットと決定的チェックのJSONは追補前のUI改善時点の記録です。
